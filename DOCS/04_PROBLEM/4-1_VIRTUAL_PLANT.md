## 1. 목표

이 프로젝트의 공장이 어떻게 생겼고 부품이 어떻게 흐르는지를 정한다. 새로 분석하는 것은 없다. 단계 3에서 데이터로 확인한 것은 "사실"로 옮겨 적고, 데이터로 확인하지 못한 것은 "가정"으로 둘지 "정하지 않음"으로 둘지를 정한다. 아래 네 가지를 정한다.

1. **부품의 흐름.** 라인 4개와 스테이션 52개를 부품이 어떤 순서로 거치는지, 어디서 길이 갈리는지, 길마다 부품이 몇 %씩 가는지를 정한다. 단계 7(시뮬레이터)이 이 흐름대로 부품을 흘린다.
2. **시간.** 스테이션 사이와 라인 사이에 시간이 얼마나 흐르는지, date 값 0.01이 실제로 몇 분인지를 정한다. 4-2에서 "예측한 뒤 조치할 시간이 얼마나 남는가"를 따질 때 쓴다.
3. **검사 지점과 불량 판정.** 부품이 불량인지(`Response`)가 공장의 어디에서, 언제 정해지는지를 정한다. 4-3의 예측 시점은 이 판정보다 앞이어야 한다.
4. **사실과 가정의 목록.** 가상 현장의 내용마다 "데이터로 확인한 사실", "이 프로젝트의 가정", "정하지 않음" 중 무엇인지 표로 적는다. 단계 4 완료 기준 2번이다.

### 4-2. 시간

결론: date 값 0.01을 6분으로 본다(가정, 컨펌 #2). 같은 라인 안에서는 시간이 거의 흐르지 않고, 라인을 옮길 때 시간이 흐른다(사실).

| 구간 | date 값의 차이 (사실) | 실제 시간 (가정) |
|---|---|---|
| 같은 라인 안의 스테이션 사이 | 0 ~ 0.02 | 0 ~ 12분 |
| L0에서 L2 | 1.0 ~ 1.3 | 10 ~ 13시간 |
| L0에서 L3 | 2.1 | 21시간 |
| L2에서 L3 | 4.8 | 2일 |
| L1에서 L2 | 18.8 ~ 26.1 | 8 ~ 11일 |
| 부품 하나의 처음부터 끝까지 (중앙값) | 3.7 | 37시간 |
| 데이터 전체 기간 | 0 ~ 1718.48 | 약 2년 |

- 선택한 이유: 생산량이 16.8마다, 그리고 그 1/7인 2.4마다 반복된다. 정확히 7배라서 16.8을 1주, 2.4를 1일로 보는 것이 자연스럽다. 확인된 것은 아니다.

### 4-3. 검사 지점과 불량 판정

결론: 검사 지점은 한 곳이다. L3의 마지막 스테이션 뒤에 "최종 검사"가 있고, 부품이 불량인지(`Response`)는 거기서 정해진다(가정, 컨펌 #1).

- 최종 검사는 데이터에 없는 스테이션이다. 이 프로젝트가 더한 것이다.
- 선택한 이유: 부품의 99.9%가 흐름의 끝까지 가고 불량 부품을 중간에 빼내지 않는다(사실). 제조 공정에서 완성된 뒤에 품질을 검사하는 것이 흔하다.
- 그래서 예측할 수 있는 세 시점("L2에 들어가기 전", "L3에 들어가기 전", "모든 스테이션을 거친 뒤")은 모두 판정보다 앞이다.
- 마지막 스테이션에서 최종 검사까지 걸리는 시간은 데이터에 없어서 정하지 않았다. "남은 시간"은 마지막 스테이션의 시각까지로 센다.

| 스테이션 번호 순서가 거치는 순서다 | 이어서 거친 스테이션 쌍 13,198,993건 중 순서가 뒤집힌 것 0건 |
| 흐름, 갈림길, 길마다의 비율 | `EDA_FINDINGS.md` 1-6 |
| 라인 안에서는 시간이 거의 흐르지 않고 라인을 옮길 때 흐른다 | 3-4의 5-3 |
| 불량 부품을 중간에 빼내지 않는다 | 부품의 99.9%가 끝까지 간다 |
| 짝(측정값이 똑같은 이웃 부품)이 있다. 부품의 7.6%, 불량률 3.65% | 3-6의 5-2 |
| `L3_S32`를 거치고 `L3_S33`을 건너뛴 부품의 불량률이 15.4%다 | 3-4의 5-6 |
| 불량률이 시기에 따라 다르다. 171개 구간 중 39개 구간에 불량의 47.1%가 있다 | 3-4의 5-4 |

아래 세 사실은 원인을 정하지 않았다. 가정도 두지 않았다.

- 짝이 생기는 이유(#4): 데이터로 설명되지 않는다.
- `L3_S33`을 건너뛰고 `L3_S32`를 거치는 이유(#5): 근거가 없다. 수리 스테이션이라는 추정은 6절에 남겼다.
- 불량이 특정 시기에 몰린 원인(#6): 계절이나 설비 이상을 알려 주는 컬럼이 없다.
