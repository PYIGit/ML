# 3-2 구조·무결성·타깃 분포(Q1~Q3)와 층화 샘플

- 상태: 구현 완료, 결과 보고 대기 (2026-11-06). 컨펌 사항 3건 확정
- 관련: `EDA_PLAN.md` Q1~Q3, 3.2절, 3.6절, 5절(3-2) / 선행: `3-1_PARQUET_CONVERSION.md`
- 입력: `DATA/raw/bosch_parquet/*.parquet` (7개)

## 1. 목표

데이터의 기본 구조(행, 식별자, 컬럼 이름 체계, 타깃 분포)를 확인해 이후 단계가 의존하는 가정(세 파일을 `Id`로 조인할 수 있다 등)을 검증하고, 이후 분석에서 재사용할 층화 샘플을 만든다.

## 2. 확인하려는 것

1. **Q1 파일 구조와 식별자**
   - 행 수, numeric·date·categorical의 `Id`가 값과 순서까지 같은가(train, test 각각)
   - `Id` 중복(파일 내, train과 test 사이), 단조성
   - train과 test의 `Id` 범위가 번갈아 섞여 있는가, 구간으로 나뉘는가
   - `train_numeric`에만 있는 컬럼이 `Response` 하나인가
   - `sample_submission`의 `Id`가 test와 값·순서가 같은가
   - 3-1 이월: numeric/date의 NaN·inf 개수, categorical 값의 형식(패턴 `^T-?\d+$` 위반, 앞뒤 공백, 소문자 변형)
2. **Q2 컬럼 이름 구조**
   - 라인 수, 라인별 스테이션 수, 스테이션별 피처 수(파일별)
   - 스테이션 번호가 여러 라인에서 중복되는가
   - 같은 스테이션의 numeric F, categorical F, date D 번호 대응(추정으로 표시): F 번호 집합이 서로소인가, D 번호가 F 번호 +1 같은 규칙을 따르는가
   - date에만 있는 스테이션(date 52개 대 numeric 50개), categorical에 없는 스테이션(34개)의 목록
3. **Q3 타깃 분포**
   - `Response`의 값 종류, 개수, 결측, 불량률과 Wilson 구간
   - 행별 비결측 numeric 컬럼 수, 방문 스테이션 수, 방문 라인 수와 `Response`의 관계(그룹 크기와 Wilson 구간 포함, 1,000개 미만 그룹 별도 표시). 경로와 경로별 불량률은 3-3
4. **층화 샘플 생성**: 불량 전체와 정상 무작위 20만 개

**Q1.** `Id`만 읽는다(메모리 부담 없음).
- 행 수는 Parquet 메타데이터에서 읽는다. `Id` 배열 비교, 중복·단조성·최소·최대는 `Id` 컬럼으로 계산한다. train과 test의 섞임 정도는 `Id`를 합쳐 정렬한 뒤 split이 바뀌는 횟수로 판정한다.
- 파싱 무결성 중 필드 수와 숫자 해석은 3-1에서 전체 기준으로 검증했으므로 MANIFEST를 인용하고 다시 하지 않는다.
- NaN·inf는 numeric/date 컬럼별로 `is_nan`, `is_infinite`를 센다(스트리밍). categorical 값의 형식은 컬럼 200개씩 나눠 읽어 전체 고유값 집합에서 검사한다(3-1에서 categorical 변환 피크가 6.1 GiB였기 때문).

**Q2.**
- `column_meta.parquet`: 파일, 컬럼, 라인, 스테이션, 종류, 피처 번호, `null_count`. `null_count`는 Parquet 행 그룹 통계에서 읽으므로 데이터를 읽지 않는다. 고유값 수는 Q6/Q7 단계에서 채운다.
- 번호 대응은 스테이션별로 번호 집합을 비교해 규칙이 성립하는 스테이션 수를 센다. 결과는 추정으로 기록한다.

**Q3.**
- `train_numeric`을 1회 스트리밍해 `row_features.parquet`(`Id`, `Response`, 비결측 수, 방문 스테이션 수, 방문 라인 수)를 만든다. 예상 메모리는 약 2.7 GiB(3-1 기준). 방문은 "스테이션의 컬럼 중 하나라도 값이 있음"이라는 프로젝트 가정을 따른다.

**층화 샘플.**
- 정상은 `numpy.random.default_rng(20261105)`로 정렬된 정상 `Id`에서 20만 개를 뽑는다(polars 버전과 무관하게 재현). 불량은 전부 포함한다. 원본 행 순서를 유지한다.
- `sample_ids.parquet`(`Id`, `Response`, `stratum`, `weight`)이 샘플 정의의 기준이다. 정상 가중치는 1,176,868/200,000 ≈ 5.88, 불량은 1이다. 비율은 전체 집계를 쓰고, 샘플로 계산할 때는 가중치를 적용한다.
- 같은 `Id`·순서로 `sample_stratified.parquet`(numeric + `Response`, 메모리 약 1.6 GB)을 만든다. date 샘플은 컨펌 사항 #2의 결과에 따른다. categorical은 Parquet이 41 MB뿐이라 샘플을 만들지 않고 `Id`로 필터해 읽는다.

**중단 조건.** 다음 중 하나가 나오면 3-3으로 넘어가지 않고 설계를 다시 본다: 세 파일의 `Id`가 일치하지 않음, `Id` 중복, train과 test의 `Id` 겹침.

**보고.** 표 4~5개(파일 구조, 컬럼 구조, 스테이션 대응, 타깃, 행별 비결측 대 `Response`)와 피크 메모리. 그림은 이 단계에서 만들지 않는다.

- (추정) D 번호가 F 번호 +1이라는 가설: date가 있는 52개 스테이션 중 41개는 D 번호가 모두 어떤 F+1과 같고, 하나도 안 맞는 스테이션은 0개다. 스테이션별 평균 비율은 D 쪽 0.953, F 쪽(F+1에 D가 있는 F의 비율) 0.566이다. 번호 인접성만 본 것이다.
- `test_date`, `test_categorical`의 컬럼은 train과 같은 이름·순서다.
