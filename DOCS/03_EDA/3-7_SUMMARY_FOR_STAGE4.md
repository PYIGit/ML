## 1. 목표

새로 분석하는 것은 없다. 3-2 ~ 3-6에서 알아낸 것을 단계 4에서 바로 쓸 수 있게 한 곳에 모은다. 아래 네 가지를 한다.

1. **단계 4 입력 요약을 쓴다.** 단계 4에서 정해야 하는 것 여섯 가지마다 "지금까지 알아낸 결론"과 "그 근거 숫자"를 적는다. 정하는 것 자체는 단계 4에서 한다.

   | 단계 4에서 정할 것 | 이 요약에 적을 것 |
   |---|---|
   | 무엇을 예측하는가 | `Response`의 뜻과 불량 부품의 수(6,879개, 0.58%) |
   | 언제 예측하는가 | 예측할 수 있는 두 시점("L3에 들어가기 전", "모든 스테이션을 거친 뒤")과 시점마다 쓸 수 있는 측정값의 양, 남은 시간 |
   | 무엇을 입력으로 쓰는가 | 남길 컬럼(numeric 927개, date는 스테이션별 시각, categorical 61개)과 불량과 관계가 강했던 두 가지("`L3_S32`를 거치고 `L3_S33`을 거치지 않음", "똑같은 짝이 있음") |
   | 학습과 검증을 어떻게 나누는가 | 불량률이 시기에 따라 다르다는 것, 똑같은 짝은 같은 시각에 있다는 것 |
   | 무엇으로 평가하는가 | 불량이 0.58%로 드물다는 것, 측정값이 같은데 `Response`가 다른 부품이 있다는 것 |
   | 가상 현장의 부품 흐름 | 스테이션 52개의 순서와 갈림길(`figures/3-3_factory_layout.png`) |

2. **`EDA_FINDINGS.md`를 "결론 먼저, 근거는 그다음" 형식으로 줄인다.** 지금은 267줄이고 Q1 ~ Q9마다 사실, 추정, 미확인이 길게 나열되어 있다. 이후 단계에서 찾아볼 때 쓰이는 것만 남긴다(컨펌 사항 #1).
3. **아직 모르는 것을 한 목록으로 모은다.** 지금은 Q마다 "미확인"이 흩어져 있고, 뒤 단계에서 이미 풀린 것도 남아 있다. 풀린 것은 지우고, 남은 것마다 어느 단계에서 다룰지 적는다.
4. **단계 3이 끝났는지 확인한다.** `EDA_PLAN.md` 6절의 완료 기준 6개를 하나씩 확인한다.

**방법**

- 단계 4 입력 요약은 `EDA_FINDINGS.md`의 맨 위에 둔다. 계획서는 "마지막 절"이라고 했지만, 결론을 먼저 적는다는 원칙(2026-11-12)에 따라 위로 올린다.
- 요약의 각 항목은 결론 한두 줄, 근거 숫자 두세 줄, 그 숫자가 나온 단계 문서의 절 번호로 적는다. 사실과 추정을 구분한다(예: "0.01이 약 6분"은 추정).
- 숫자를 옮길 때마다 원래 단계 문서의 값과 같은지 대조한다. 3-5의 짝 수치(4.1%, 3.47%)는 3-6에서 고쳐진 값(7.6%, 3.65%)을 쓴다.
- 완료 기준 6개는 기준마다 "충족" 또는 "미충족"과 확인한 근거 한 줄을 표로 적는다. "스크립트만으로 모든 표와 그림을 다시 만들 수 있다"는 단계 문서의 출력 파일마다 그것을 만드는 스크립트가 있는지로 확인한다. 전체 재실행은 하지 않는다(각 단계에서 스크립트로 실행하고 검증했다).
- `EDA_FINDINGS.md`를 고치기 전에 지금 상태가 Git에 커밋되어 있는지 확인한다. 커밋되지 않은 변경이 있으면 그 내용 위에서 작업한다.

## 6. 다음 단계로 넘기는 것

- 단계 4(문제 정의 및 가상 제조 현장 설계)의 출발점은 `EDA_FINDINGS.md` 1절이다. 정할 것은 여섯 가지다: 무엇을 예측하는가, 언제 예측하는가, 무엇을 입력으로 쓰는가, 학습과 검증을 어떻게 나누는가, 무엇으로 평가하는가, 가상 현장의 부품 흐름.
- 그중 EDA가 답을 주지 못해 직접 정해야 하는 것은 세 가지다.
  - 예측 시점: "모든 스테이션을 거친 뒤"인가, "L3에 들어가기 전"인가.
  - 짝(측정값이 똑같은 이웃 부품)을 입력으로 쓸 것인가.
  - 부품의 시각을 입력으로 쓸 것인가.
- 가정으로 둘지 정해야 하는 것 5개는 `EDA_FINDINGS.md` 2절에 있다.
- 미해결(이전 단계에서 이어짐): 워킹 트리 CRLF와 인덱스 LF의 불일치 정리 방법 결정.
