## 2. EDA가 답해야 할 질문

번호는 수행 순서이기도 하다. 각 질문의 답은 "확인된 사실 / 추정 / 미확인"으로 구분해 `EDA_FINDINGS.md`에 기록한다.

### Q1. 파일 구조와 식별자

- train/test 각각 행 수는 몇 개인가
- `Id`는 numeric, categorical, date 세 파일에서 동일한 집합이고 동일한 순서인가 (조인 키로 쓸 수 있는가)
- train과 test의 `Id` 범위는 어떻게 겹치는가 (번갈아 섞여 있는가, 구간으로 나뉘는가)
- `train_numeric`에만 있는 컬럼 1개가 `Response`인가
- `Id` 중복 여부 (파일 내, 그리고 train과 test 사이)
- `sample_submission.csv`의 `Id`가 `test_*`의 `Id`와 일치하는가
- 파싱 무결성: 모든 행의 컬럼 수가 헤더와 같은가, numeric/date 컬럼에 숫자로 해석되지 않는 값이 있는가, 문자열 컬럼에 공백이나 대소문자 변형이 섞여 있는가

### Q2. 컬럼 이름 구조

- 컬럼명 `L{line}_S{station}_{F|D}{num}`을 파싱해 라인 수, 라인별 스테이션 수, 스테이션별 피처 수를 표로 만든다.
- 같은 스테이션의 F(numeric), F(categorical), D(date) 번호가 어떻게 대응하는지 확인한다. 예: `L0_S0_D1`이 `L0_S0_F0`의 측정 시각인지는 번호 인접성으로 추정만 가능하다. 추정으로 표시한다.
- 스테이션이 여러 라인에 걸쳐 중복 번호를 쓰는지 확인한다.

### Q3. 타깃 분포

- `Response` 값의 종류와 각각의 개수, 불량률
- 결측 여부
- 행별 비결측 컬럼 수, 방문 스테이션 수, 방문 라인과 `Response`의 관계 (Q4 결과와 연결)

### Q4. 결측 구조와 공정 경로

Bosch 데이터는 결측 자체가 정보일 가능성이 크다. 부품이 어떤 스테이션을 거쳤는지 결측 패턴으로 드러날 수 있다.

- 컬럼별 결측률 분포 (전부 비어 있는 컬럼, 거의 비어 있는 컬럼의 수)
- 행별 비결측 컬럼 수의 분포
- 스테이션 단위 "방문 여부" 정의: 해당 스테이션의 컬럼 중 하나라도 값이 있으면 방문으로 본다. 이 정의는 프로젝트의 가정임을 명시한다.
- 부품별 방문 스테이션 집합(경로)의 종류와 빈도. 상위 경로 N개가 전체의 몇 %를 차지하는가
- 경로별 불량률. 상관이지 인과가 아님을 명시한다.
- 라인 간 관계: 한 부품이 여러 라인을 거치는가, 라인이 배타적인가
- 결측 유형 구분: 스테이션을 거치지 않아 생기는 구조적 결측과, 거친 스테이션 안에서 일부 피처만 비어 있는 산발적 결측을 나누어 센다. 전처리 전략(단계 5)이 달라지기 때문이다.
- 교차 파일 일관성: numeric 기준 방문 여부와 date 기준 방문 여부, categorical 기준 방문 여부가 서로 일치하는가. 불일치가 있으면 그 규모와 패턴을 기록한다.

### Q5. 시간(date) 구조

- date 값의 범위, 단위 추정 (정수부와 소수부의 의미는 데이터로만 추정)
- 같은 스테이션 안의 D 컬럼들이 행 내에서 동일한 값을 갖는지 (그렇다면 스테이션당 시각 1개로 축약 가능)
- 부품별 최초 시각, 최종 시각, 소요 시간 분포
- 스테이션 간 시각 순서로 추정한 흐름(부품이 이어서 거친 스테이션 쌍과 그 사이 시각 차이). 어디까지나 데이터에서 관찰된 순서이며 실제 공정 배치로 단정하지 않는다.
- 시간에 따른 생산량과 불량률 추이 (시간 구간별)
- 불량의 시간적 군집성: 불량이 시간축에서 고르게 퍼져 있는가, 특정 구간에 몰려 있는가(버스트). 몰려 있다면 그 구간의 위치와 길이를 기록한다. 분할 전략(단계 4)과 운영 시스템의 위험도 설계에 영향을 준다.
- `Id` 순서와 시각 순서의 관계: `Id`가 시간에 따라 단조 증가하는가, 아니면 섞여 있는가 (Q8의 근거)

### Q6. numeric 피처 특성

- 컬럼별 고유값 수, 상수 컬럼, 서로 완전히 동일한 컬럼, 사실상 이산형인 컬럼. 제거하거나 다르게 다룰 컬럼을 정하는 근거다.
- 중복 행: 측정값이 완전히 같은 부품 쌍이 있는가, 있다면 얼마나 많고 `Response`는 일치하는가
- 값의 범위와 스케일: 피처들의 평균과 분산이 비슷한 범위에 있는가(이미 정규화된 값인지 추정). 정규화되어 있다면 물리적 단위 해석은 불가능함을 기록한다.
- 이상치와 센티널 값: 극단값의 빈도, 특정 값(예: 0, -999 같은 반복되는 값)이 결측 대용으로 쓰였을 가능성

### Q7. categorical 피처 특성

- 컬럼별 고유값 수
- 컬럼별 최빈값 비율: 비결측 값의 대부분이 한 가지 값(예: `T1`)이라면 정보량이 거의 없다.
- 위 두 가지와 3-3의 결측 결과(컬럼의 85.4%가 99% 이상 결측, 부품의 19.4%는 값이 없음)로 이 파일을 쓸지, 쓴다면 어느 컬럼을 남길지 판단한다.

### Q8. 예측 시점에 이용 가능한 정보 (누수 검토)

단계 4의 문제 정의에서 가장 중요한 입력이다.

- 최종 품질 검사 결과(`Response`)가 결정되는 시점과 각 스테이션 측정 시점의 관계
- "모든 스테이션을 거친 뒤 예측"과 "중간 스테이션까지의 정보로 조기 예측" 중 어느 설정이 데이터로 뒷받침되는가
- `Id` 순서나 인접 부품 정보처럼 대회에서 알려진 기법이 운영 시스템 관점에서 정당한 입력인지 검토. 결론은 단계 4로 넘기되, 근거가 되는 관찰(예: `Id` 순서와 시각의 관계)은 이 단계에서 확인한다.

## 3. 방법

### 3.1 Parquet 변환 (EDA 전 선행 작업)

CSV 하나가 2~2.7 GiB이고 메모리는 7.6 GiB이므로 CSV를 반복해서 읽는 방식은 비현실적이다. 한 번 Parquet으로 변환하고 이후에는 필요한 컬럼만 읽는다.

- 출력 위치: `DATA/raw/bosch_parquet/` (사용자 결정). 원본 CSV와 분리하되 "원본의 무손실 변환본"이라는 의미로 `raw/` 아래에 둔다.
- 파일 구성: CSV 1개당 Parquet 1개, 행 순서 유지. 예: `train_numeric.parquet`
- 자료형 (무손실 원칙. 다운캐스팅은 단계 5에서 결정)

| 대상 | 자료형 | 근거 |
|---|---|---|
| `Id` | Int64 | 정수 식별자 |
| numeric `F*` | Float64 | 소수 3자리 실수. Float32는 손실 가능성이 있어 변환본에서는 쓰지 않음 |
| date `D*` | Float64 | `82.24` 형식의 실수 |
| categorical `F*` | Utf8 (문자열) | `T1` 형식. 범주형 인코딩은 단계 5에서 |
| `Response` | Int8 | 0/1로 추정. 변환 후 값 종류 확인 |

- 방식: 스트리밍(lazy scan → sink). 전체를 메모리에 올리지 않는다.
- 검증: 변환 후 행 수가 CSV의 행 수(헤더 제외 줄 수)와 같은지, 컬럼 수가 같은지, 무작위 샘플 행 수십 개의 값이 CSV와 일치하는지 확인한다. 추가로 컬럼 몇 개를 골라 CSV 스트리밍 집계와 Parquet 집계의 결측 수와 합계가 일치하는지 비교한다. 파싱은 엄격 모드로 실행해 숫자로 해석되지 않는 값이 있으면 조용히 null로 바뀌지 않고 실패하도록 한다. 결과를 `DATA/raw/bosch_parquet/MANIFEST.json`에 기록한다.
- 재현: `scripts/convert_bosch_to_parquet.py`로 작성하고 실행 명령을 문서화한다.

### 3.2 메모리 전략

- train_numeric을 Float64로 전부 올리면 약 9 GB라 불가능하다. 다음 규칙을 따른다.
  - 집계(결측 수, 고유값 수, min/max)는 lazy 스트리밍 집계로 계산한다.
  - 분포 시각화는 컬럼 일부만 읽거나 행 샘플을 쓴다. 불량률이 1% 미만으로 예상되므로 단순 무작위 샘플에는 불량이 수백 개밖에 들어가지 않는다. 불량 전체 + 정상 무작위 샘플(예: 20만 행)의 층화 샘플을 만들어 `DATA/interim/eda/`에 저장하고 재사용한다. 샘플 사용 시 문서에 표시하고, 비율 계산에는 샘플이 아닌 전체 집계를 쓴다.
  - 모든 샘플링과 무작위 선택에는 고정 시드를 쓰고 시드를 기록한다.
  - 스테이션 방문 여부 행렬은 부품 수 × 스테이션 수(약 1.18M × 50~60)로 작아서 메모리에 올릴 수 있다.
- 각 분석 스크립트는 피크 메모리를 기록해 다음 단계 설계에 참고한다.

### 3.6 소표본 집계의 통계적 주의

- 경로별, 스테이션별, 시간 구간별 불량률처럼 그룹을 나눠 비율을 계산할 때는 그룹 크기를 함께 기록하고, 최소 표본 수(예: 1,000개) 미만 그룹은 별도로 표시한다.
- 비율에는 신뢰구간(Wilson 구간)을 붙여, 그룹 간 차이가 표본 오차 범위 안인지 밖인지 구분한다. 불량이 희소하므로 작은 그룹의 불량률은 쉽게 과장된다.
- 많은 그룹을 비교하면 우연히 큰 차이가 보이는 그룹이 반드시 나온다. 눈에 띄는 그룹은 가설로 기록하고, 결론으로 쓰지 않는다.
